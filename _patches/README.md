## 二、怎么跑

```bash
cd _patches
node _driver.js                      # 默认基线 baseline\InternalBeyond-b0d7919d.html → out\InternalBeyond.patched.html ＋ out\_自检报告.md
node _driver.js --dry                # 只跑自检，不写文件
node _driver.js --only p01           # 只应用某一集
node _driver.js --baseline baseline\InternalBeyond-9ef2ed12.html   # 用旧基线对照（锚点按当前基线校验，更老的基线上会报命中 0 次）
node _driver.js --out ..\InternalBeyond.html   # 直接产出到电脑端在用文件（默认不这么做，见下）
node _test_pipeline.js               # 流水线反向验证（13 条）
node _test_p01_ping.js               # P01 逻辑层断言（33 条，两级探活）
node _test_p07_summary.js            # P07 逻辑层断言（25 条）
node _smoke_ui_edge.js             # Edge 界面冒烟（仅系统 Edge，不装 Chrome）
```

**默认不把产物写回 `InternalBeyond.html`** —— 验收通过后由主控决定何时替换（当前那份是补丁产物；干净基线始终在 `baseline\`，重放不受影响）。

## 三、自检三层（任一不过 → **不写产物**、非零退出）

| 层 | 查什么 |
|---|---|
| HTML 结构完整 | 以 `</html>` 收尾、有 `<html>`；script / div / button / span / textarea / select 的**开闭差值与原文一致** |
| JS 语法可解析 | 逐个 script 块 `new vm.Script`；坏块数**不得超过**原文 |
| 新增/原有锚点核对 | `guards`（原有锚点必须还在）＋ `adds`（新增锚点必须出现） |

外加两道硬断言：每处锚点命中数必须等于预期（默认 1，上游改过就停下）、`expectCount` 必须等于清单实际条数。

- **转义**：清单里的锚点与产出代码一律用 `String.raw` —— 普通模板字符串会吃掉 `\.` / `\s` 里的反斜杠（手机端清单踩过一次，差 1 字节，靠 sha256 比对才抓出来）。
